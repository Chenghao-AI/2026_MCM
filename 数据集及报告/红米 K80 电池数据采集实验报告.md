# 红米 K80 电池数据采集实验报告

## 1. 实验背景与核心目标 
本实验旨在构建一套基于 ADB 和 Python 的自动化数据采集系统，专门针对红米 K80（HyperOS/Android 系统）进行电池性能分析。实验的核心目标是解决**USB连接充电导致的数据污染问题**，在保障手机与电脑数据传输的同时，切断充电通路，从而获取纯净的放电数据。

系统将实时采集以下 **12 个关键参数**，为后续的美赛 A 题建模提供高精度数据支持：
1. **时间参数**：相对时间 (s)、标准时间字符串
2. **电池状态**：SOC (%)、电池温度 (℃)
3. **处理器功耗**：CPU 频率 (GHz)、CPU 耗电功率 (mW)、GPU 频率/功率（估算）
4. **显示参数**：屏幕亮度
5. **网络参数**：网络类型 (WiFi/Cellular)、信号强度 RSRP (dBm)、信噪比 SINR (dB)、信噪比 SNR (dB)
6. **环境参数**：环境温度 (℃)
7. **系统负载**：后台应用数量

## 3. 核心技术方案：消除 USB 充电干扰

针对连接 USB 线会导致电池充电、干扰真实放电曲线的问题，本实验采用 **ADB 指令控制 + 脉冲更新策略**。

### 3.1 阻断充电
使用 Android 底层电源管理指令强制切断 USB 供电通路：
```bash
adb shell dumpsys battery set usb 0
# 备选指令（适配部分旧版系统）：adb shell dumpsys battery set unplugged 1
```
*验证标准：手机状态栏充电图标消失，`dumpsys battery` 输出中显示 `USB powered: false`。*

### 3.2 解决“数据冻结”问题 (Pulse Update)
在 HyperOS 等新系统中，单纯禁用 USB 充电可能导致电池广播停止更新（SOC 锁死）。本实验编写的 Python 脚本采用了**脉冲更新算法**：
*   **常态**：保持 `usb 0` 状态，确保不充电。
*   **脉冲**：每隔 45 秒瞬间执行 `reset` 恢复供电 1.5 秒，抓取最新硬件库仑计数值，随即立刻再次切断供电。
*   **推算**：在两个脉冲之间的“盲区”，利用死位推算（Dead Reckoning）算法，根据平均电流线性模拟 SOC 的微小下降，实现 4 位小数的高精度连续记录。

## 6. 数据处理与校准

### 6.1 数据导出与清洗
1.  **格式转换**：将生成的 `.csv` 文件导入 Excel，设置 UTF-8 编码，分列符为逗号。
2.  **异常值清洗**：剔除因 ADB 连接波动产生的空行或重复时间戳数据。

### 6.2 数据补全
*   **环境温度**：将脚本中的默认值 `25.0` 批量替换为实验期间实测的室温。
*   **信号参数**：若部分时段 RSRP 显示为 `-999`（系统权限限制），需根据实验记录（如“WiFi 满格”对应 -30dBm，“5G 弱信号”对应 -110dBm）进行插值补全。

### 6.3 衍生特征计算
在 Excel 中新增列，计算 SOC 变化率以作为建模的标签值 (Label)：
$$ \text{SOC\_Drop\_Rate} = \frac{\text{SOC}_{t} - \text{SOC}_{t-1}}{\text{Time}_{t} - \text{Time}_{t-1}} $$

## 7. 常见问题排查 (Troubleshooting)

1.  **ADB Unauthorized**：
    *   *现象*：`adb devices` 显示 unauthorized。
    *   *解法*：手机“开发者选项” -> “撤销 USB 调试授权”，重新插拔并点击“始终允许”。
2.  **频率/功率读数为 0**：
    *   *原因*：HyperOS 限制非 Root 用户读取 `/sys/class/powercap` 等节点。
    *   *解法*：脚本已内置估算逻辑（电压 $\times$ 电流 $\times$ 负载系数）；也可配合 PerfMon APP 辅助记录。
3.  **实验后无法充电**：
    *   *原因*：实验结束后未执行重置指令。
    *   *解法*：执行 `adb shell dumpsys battery reset` 或重启手机。
