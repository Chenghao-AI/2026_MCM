## 二、赛题概述

智能手机是现代生活的必备工具，但电池表现常常"难以预测"：有时能撑一整天，有时午饭前就快速耗尽。耗电并非只取决于"用得多"，而是**屏幕尺寸与亮度、处理器负载、网络活动、后台应用**（即使设备看似空闲也在耗电）等多因素相互作用的结果；**环境温度**会让电池在寒冷时有效容量下降、在持续高负载下过热；电池行为还受其**历史与充电方式（老化）**影响。

赛题要求建立一个**连续时间（continuous-time）数学模型**，输出真实使用条件下电池荷电状态（SOC）随时间的变化，用于预测不同条件下的**剩余续航时间（Time-to-Empty）**，假设手机使用锂离子电池。

四项核心任务：

1. **连续时间模型**：用连续时间方程（组）描述 SOC，从最简合理的耗电模型出发，逐步纳入屏幕、处理器、网络、GPS、后台任务等因素；数据仅用于参数估计与验证，**禁止仅靠离散曲线拟合、时序回归或黑箱机器学习**。
2. **续航预测**：在不同初始电量与使用场景下计算/逼近 Time-to-Empty，与观测或合理行为对比，量化不确定性，识别模型优劣与各场景下的快速耗电驱动因素。
3. **敏感性与假设**：考察建模假设、参数取值、使用模式波动对预测的影响。
4. **建议**：将结论转化为面向用户的实用建议（降亮度、关后台、切换网络模式等），并讨论操作系统节电策略、电池老化导致的容量衰减，以及框架向其他便携设备的推广。

## 三、建模体系总览

整体工作以"**机理驱动 + 数据标定**"为核心，构建了一个耦合的连续时间动力系统，由三大模块 + 两条扩展组成，逻辑结构如下：

```
                        ┌─────────────────────────────────────┐
   用户输入             │       SOC 时间演化模型（核心）        │
  ┌──────────┐          │  E_eff · dSOC/dt = −P_tot           │
  │ 使用场景  │─────────▶│  P_tot = P_CPU + P_net + P_dis      │
  │ 亮度设置  │          └─────────────────────────────────────┘
  └──────────┘                 │            │            │
                               ▼            ▼            ▼
                        ┌────────────┐ ┌──────────┐ ┌────────────┐
  网络环境输入          │  CPU 模型  │ │ 网络模型  │ │  显示模型   │
  ┌──────────┐         │  (Eq. 9)   │ │ (Eq.10-13)│ │  (Eq. 14)  │
  │ RSRP/SNR │         └────────────┘ └──────────┘ └────────────┘
  └──────────┘                 └────────────┬────────────┘
                                            ▼
                                   ┌─────────────────┐
                                   │   温度模型       │  Newton 冷却定律
                                   │  C·dT/dt (Eq.3) │  + 热节流 u(T)
                                   └─────────────────┘
                                            │
              ┌─────────────────────────────┴──────────────────────────┐
              ▼                                                         ▼
   ┌────────────────────┐                                    ┌────────────────────┐
   │ 温度对容量的影响    │                                    │   电池老化模型      │
   │ E_eff(T) (Eq.7-8)  │                                    │ Arrhenius (Eq.15-17)│
   └────────────────────┘                                    └────────────────────┘
```

模型的两条物理主线：

- **能量守恒主线**：电池有效能量的减少速率 = 整机各模块瞬时耗电功率之和。
- **牛顿冷却主线**：元件耗电产生的废热使手机升温，手机又按温差向环境散热；高温触发 CPU/GPU 降频（thermal throttling）。

### 核心方程

**（1）SOC 时间演化方程（能量守恒）**

$$
E_{eff}\frac{dSOC}{dt}=-P_{tot}\qquad\text{(1)}
$$

$$
P_{tot}=P_{CPU}+P_{net}+P_{dis}\qquad\text{(2)}
$$

其中 $E_{eff}$ 为锂电池有效总能量（J）， $P_{tot}$ 为整机总功率（W），按功耗来源分解为 CPU、网络、显示三部分。

**（2）温度演化方程（Newton 冷却定律 + 热节流）**

$$
C\frac{dT}{dt}=(1-\eta_0)P_{CPU}+(1-\eta_n)P_{net}+(1-\eta_d)P_{dis}-\lambda S(T-T_0)\qquad\text{(3)}
$$

各 $\eta$ 为对应元件的能量利用效率（有效功率占比），其余为废热；最后一项为向环境的散热。高温触发降频：

$$
f=f_0\,u(T),\qquad f_{dis}=60\,u(T)\qquad\text{(4-5)}
$$

$$
u(T)=\begin{cases}1, & T\le T_0\\ u_{min}+(1-u_{min})e^{-\frac{T-T_0}{\tau}}, & T>T_0\end{cases}\qquad\text{(6)}
$$

**（3）温度对电池有效容量的影响**

$$
E_{eff}=\frac{E_{eff}(25)}{F(25)}F(T),\qquad F(T)=0.0026T^3-1.2176T^2+73.8623T+9933.3511\qquad\text{(7-8)}
$$

### 三大子模型

**CPU 模型**（式 9）：由后台静态功耗 + 当前任务动态功耗 + 下载数据处理功耗三部分组成。

$$
P_{CPU}=\frac{1}{\eta_0}\big(P_0+k_0 f+\alpha f I_{down}\big)\qquad\text{(9)}
$$

- $P_0$：后台活动维持的恒定功耗； $k_0$：任务相关的频率-功耗系数（游戏最大）； $f$：CPU 主频； $\alpha$：处理单位下载数据的能耗系数； $I_{down}$：平均下载速率。

**网络模型**：

- 工作模式（式 10-12）：射频前端（RF Front-End）维持连接的功耗 + 下载数据处理功耗。

$$
P_{net}=\frac{1}{\eta_n}\big(P_{RF}\tfrac{I_{down}}{v_{down}}+\beta I_{down}\big)\qquad\text{(10)}
$$

$$
P_{RF}=\min\big(P_{max},\,P_0\cdot 10^{-(RSRP-30)/10}\big)\qquad\text{(11)}
$$

$$
v_{down}=B\log_2\big(1+10^{(SNR-30)/10}\big)\qquad\text{(12)}
$$

- 待机模式（式 13）：后台仅少量下载，考虑信令爬坡能量（ramping energy）与尾能量（tail energy）。

$$
P_{net}=\frac{1}{\eta_n}(f_n E_0+\beta I_{down})\qquad\text{(13)}
$$

**显示模型**（式 14）：OLED 自发光像素功耗 + 显示驱动电路（DDIC）动态刷新功耗。

$$
P_{dis}=\frac{(k_1 L+k_2 f_{dis})S\rho}{\eta_{dis}}\qquad\text{(14)}
$$

- $L$：归一化亮度； $S$：屏幕面积； $\rho$：像素密度； $f_{dis}$：屏幕刷新率。

### 电池老化模型（扩展）

基于 Arrhenius 定律描述有效容量随时间的缓慢衰减：

$$
\frac{dE_{eff}}{dt}=-kE_{eff}, \qquad k=A\exp\!\Big(\frac{E_a}{RT}\Big)\qquad\text{(15-16)}
$$

$$
\frac{\Delta E_{eff}}{E_{eff}}=1-e^{-\int_0^T k\,dt}\qquad\text{(17)}
$$

单次放电循环内 $E_{eff}$ 变化很小，可视为常数，经验参数取 $A=10^6\,\text{year}^{-1}$， $E_a=50\,\text{kJ·mol}^{-1}$。

## 五、数据采集实验（红米 K80）

由于公开的高质量手机电池放电数据集有限，团队**自行搭建了一套基于 ADB + Python 的自动化数据采集系统**，对测试机进行实测。

### 测试设备

- **机型**：红米 REDMI K80（型号 24117RK2CC），HyperOS / Android 16
- **电池**：6550 mAh（typ）
- **处理器**：第三代骁龙 8 移动平台（八核，最高 3.3 GHz）
- **内存**：12.0 + 4.0 GB；**分辨率**：3200×1440；**屏幕**：6.67"

### 核心技术：消除 USB 充电干扰

USB 连接电脑会同时给手机充电，污染放电数据。采集系统采用两项关键技术：

1. **ADB 指令阻断充电**：`adb shell dumpsys battery set usb 0` 强制切断 USB 供电通路，保留数据传输。
2. **脉冲更新策略（Pulse Update）**：HyperOS 下单纯禁用充电会导致电池广播停更（SOC 锁死）。脚本每 45 秒瞬间 `reset` 恢复供电 1.5 秒、抓取硬件库仑计真实值后立即再次切断；两次脉冲之间的"盲区"用**死位推算（Dead Reckoning）**，依据平均电流线性推算 SOC，实现 4 位小数的连续高精度记录。

### 采集的 12 个参数

相对时间、标准时间、SOC(%)、电池温度、CPU 频率、CPU 功率、屏幕亮度、网络类型（WiFi/蜂窝）、RSRP、SINR、SNR、环境温度（另含后台应用计数，共 13 列）。

## 六、主要结果

### 1. 四种使用场景的续航预测

**确定性预测（Time-to-Empty）**

| 场景         | 打游戏      | 看视频      | 刷网页      | 待机          |
| :----------- | :---------- | :---------- | :---------- | :------------ |
| 续航（小时） | 3.8（3.82） | 3.2（3.20） | 6.7（6.66） | 25.7（25.68） |

**Monte Carlo 不确定性分析（100 次，对 $f_0$、 $I_{down}$、 $T_{env}$ 引入随机波动）**

| 场景   | 平均续航（h） | 标准差（h） |
| :----- | :------------ | :---------- |
| 游戏   | 4.1           | 1.2         |
| 视频   | 3.3           | 1.1         |
| 刷网页 | 6.6           | 1.7         |
| 待机   | 26.8          | 5.06        |

待机模式因绝对历时长，最终结果的不确定性（标准差）显著大于其他三种场景。

### 2. 各场景耗电驱动因素（功耗占比）

| 场景             | 网络（Net）     | CPU             | 显示（Dis）     | 主要驱动因素                                |
| :--------------- | :-------------- | :-------------- | :-------------- | :------------------------------------------ |
| **游戏**   | 33.1%           | **40.6%** | 26.3%           | 三者接近，**CPU 主导**（40.6%）       |
| **视频**   | **55.5%** | 22.4%           | 22.1%           | **网络主导**（下载数据量大）          |
| **刷网页** | 23.1%           | 31.1%           | **45.9%** | **显示主导**（文本页面、计算/下载少） |
| **待机**   | 6.2%            | **93.8%** | —              | **CPU 后台任务主导**（93.8%）         |

### 3. 各因素对续航的影响

- **屏幕亮度**：亮度从最强调到最暗，续航仅增加约 **4%**（3.88h → 约 3.73h 区间），但会显著损害使用体验。
- **信号环境**：
  - **RSRP 几乎无影响**：模型中 $P_{max}$ 限制了发射功率上限，弱信号下手机不会无限增大发射功率，故 RSRP 影响可忽略。
  - **SNR 影响明显且存在饱和**：SNR 从 −30 dB 提升到约 −10 dB 时续航快速增加（低 SNR 时链路低效、发射时间长、功耗大）；超过 −10 dB 后增益趋缓并饱和。
- **环境温度**：影响最大。环境温度升高到约 32°C 时手机热平衡温度超过 45°C，触发降频，CPU 主频与刷新率下降，功耗降低、续航显著延长（约 3.25h → 4.78h）；但代价是计算变慢、画面卡顿。低温下电池有效容量下降。
- **后台负载（$P_0$）**：待机模式下，CPU 后台功耗每变化 0.01 W，续航变化约 40 分钟，改善明显。

### 4. 电池老化（容量衰减，论文 Table 8）

| 场景   | 时长 (h) | 单次容量损失率        | 平均温度 (°C) | 每小时损失率          |
| :----- | :------- | :-------------------- | :------------- | :-------------------- |
| 游戏   | 3.82     | $1.73\times10^{-6}$ | 38.07          | $4.53\times10^{-7}$ |
| 视频   | 3.20     | $1.70\times10^{-6}$ | 40.78          | $5.31\times10^{-7}$ |
| 刷网页 | 6.66     | $1.99\times10^{-6}$ | 31.28          | $2.99\times10^{-7}$ |
| 待机   | 25.68    | $6.00\times10^{-6}$ | 27.43          | $2.33\times10^{-7}$ |

待机因单次历时长，单次循环的累计容量损失最大；视频因平均温度最高，每小时损失率最高——温度对电池老化有显著影响。

### 5. 核心结论

- **因素影响排序**：环境温度（Environment Temperature） > 屏幕亮度（Brightness） ≫ 网络环境（Network Environment）。
- **场景续航排序**：打游戏 ≈ 看视频 < 刷网页 ≪ 待机。

## 七、面向用户的建议

1. **改变使用方式最有效**：在需要省电时，减少高耗电活动（游戏、视频），改用低能耗方式（浏览文本网页、待机），通常可使续航时间翻倍，代价是牺牲部分娱乐功能。
2. **降低屏幕亮度收益有限**：最多延长约 4% 的续航，却明显影响观感，不建议作为主要节电手段。
3. **避免高温环境**：高温会触发降频导致卡顿、并加速电池老化；避免在阳光直射、充电时运行高负载任务，应主动为手机散热。
4. **清理后台应用可显著延长待机时间**：待机时 CPU 功耗中后台任务占比高达 93.8%；定期清理微信、Instagram 等常驻后台、频繁唤醒 CPU 的应用，可延长待机约 2–4 小时。

## 八、敏感性 / 稳定性分析

- 对通过实验拟合、不确定性较大的关键系数 $k_0$ 做了 ±30%（70%/100%/130%）的敏感性分析：
  - 三组实验共用同一组随机使用场景与外部条件（"先 70% 组开路、后 100%/130% 组跟随"的两阶段设计），保证只有 $k_0$ 不同。
  - 结果显示模型对 $k_0$ **呈中等程度敏感**： $k_0$ 变化直接影响 CPU 频率对功耗的作用，但不改变 SOC 与温度演化的整体趋势，模型稳定性可接受。
- 另对 5 个拟合参数（$\gamma$、 $P_0$、 $\alpha$、 $k_1$、 $k_2$）做了 −90%~+90% 的扫描，均呈近似线性的温和影响。

### 模型的优势与不足

**优势**

- 直接建立在连续时间 SOC 与温度演化方程之上，由能量守恒导出，耗电由物理可解释的功率项决定，满足赛题对"明确物理机理"的硬性要求。
- CPU/网络/显示三大子模型可独立解释、参数化与分析，能基于真实数据灵活拟合，模拟真实场景。
- 模型灵活、可适应不同环境温度与使用场景，适用面广。

**不足**

- 拟合参数基于公开实验数据与团队少量实测，预测与实际使用可能存在偏差。
- 模型对信号环境不够敏感，而实测数据显示信号因素实际可能导致约 5% 的耗电速度波动。

## 十二、运行与复现

### 环境依赖

- **Python 3.10+**（实测 Python 3.13/3.14 可运行）
- 核心库：`numpy`、`scipy`、`pandas`、`matplotlib`、`openpyxl`
- 数据采集额外需要：ADB Platform-tools（配置到环境变量 Path）、一台开启 USB 调试的 Android 设备
- MATLAB 脚本需 MATLAB（含 Curve Fitting 基础函数，无需额外工具箱）

### 复现步骤

1. 数据采集（可选，已有数据可跳过）：手机开启开发者模式与 USB 调试，连接后运行 `python battery_data_logger.py`，结束后执行 `adb shell dumpsys battery reset` 恢复充电。
2. 数值仿真：运行 `Master_Equation4_运行一次算多个微分方程.py` 得到 Monte Carlo 续航分布；运行 `模拟真实连续使用手机.py` 得到混合场景连续演化。
3. 出图：运行 `生成四宫格.py`、`四模式下的重复计算.py` 等生成对应论文图片。
4. 参数拟合：在 MATLAB 中运行 `CPU频率和功率的拟合.m`、`温度_Mean Value拟合.m`（注意将数据文件置于工作目录或修改文件路径）。
